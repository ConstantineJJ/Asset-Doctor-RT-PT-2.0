# Первый Heal G002 в desktop — отчёт 2026-11-17

Ветка `claude/g002-heal` от `24f9fc6`. Основание — ТЗ-G002 v1.0 и
[ADR-0031](DECISIONS/ADR-0031-atomic-edit-publication.md). Исполнитель — Claude.
Ветка не отправлена в GitHub и не слита в `main`; PR не создавался (нужна команда владельца).

## Что теперь умеет программа

1. Открыть GLB → «Диагностика» → у строки G002 «Предпросмотр ремонта…».
2. Фоновый расчёт: полный план (не 16 примеров), независимая проверка удаления,
   проверка пригодности к сохранению (G002-06), снимок и полный анализ результата
   для будущей ревизии. Модель, история и GPU не меняются; подготовку можно отменить.
3. Окно предпросмотра: примитив, ссылки из узлов (включая неактивные, это не видимые
   копии), до/после, останется ли G002 по полному анализу, совместимость с экспортом,
   оценка геометрии на GPU. «Применить» или «Отмена».
4. «Применить» публикует атомарно: история Session, индексы, сцена и поколение
   (снимок, отчёт, метка) меняются вместе или не меняются вовсе.
5. «Отменить правку» / «Вернуть правку» (Ctrl+Z / Ctrl+Y) — той же публикацией.
6. «Сохранить копию…» (Ctrl+Shift+S): проверенный GLB только в новый файл,
   побайтный readback с диска, независимый повторный импорт и сверка. Исходный и
   существующие файлы не перезаписываются; рабочий файл не меняется.
7. «* не сохранено» в панели и «*» в заголовке, пока ревизия/origin отличаются от импорта или
   последней проверенной копии. При закрытии и открытии другой модели с несохранёнными
   правками — вопрос «Да — сохранить копию / Нет — без сохранения / Отмена».

## Архитектура (кратко)

| Состояние | Владелец |
|---|---|
| Документ, ревизии, Undo/Redo | `ad_commands::Session` (одна история) |
| Снимок + отчёт + метка | `Generation` в `PreparedAsset`, заменяется целиком |
| GPU-сцена | `Renderer`, `stage_scene` → `activate` |
| Фоновые задачи | один обобщённый `worker::Worker` для импорта, правок и сохранения |
| Подтверждённое состояние на диске | `saving::Confirmed` (импорт или квитанция `SavedCopy`) |

Публикация: устаревание → `Arc::get_mut` (иначе «занято») → `Session::stage_*` →
`Renderer::stage_scene` → безотказные `publish` + `activate` + замена поколения.
Компенсация «commit → сбой → Undo» не используется.

## Проверки

197 тестов (36 analysis / 17 commands / 38 desktop / 27 document / 41 formats /
12 heal / 13 renderer / 13 storage); fmt --check, clippy all-targets -D warnings,
release-сборка, cargo-deny. Нативные smoke с запрошенной sync-validation; фактическое
значение настройки слоя отдельно не проверялось.

## Замеры

Тяжёлая авторская модель (`tools/make_heavy_heal_fixture.py` → `artifacts/`,
1535378 треугольников, текстура 2048²): подготовка в фоне 281–406 мс, публикация в
UI-потоке 39–44 мс (GPU 33–37 мс). На время публикации на GPU две сцены
(≈ 2 × 113 МБ по учёту выделений); текстуры перезаливаются. Единичные локальные
замеры, не бенчмарк; VRAM драйвера не измерялась (нет VK_EXT_memory_budget).

## Ручная проверка владельцем (2026-11-17)

Программа запущена из терминала с `Duplicate_Heal.glb`, `--require-validation`, лог в
ignored `artifacts/manual-ui/`. Владелец сообщил, что прошёл все пункты чек-листа
и всё совпало с критериями, и приложил два снимка: окно «Диагностика» со строкой
G002 и кнопкой «Предпросмотр ремонта…», окно предпросмотра (примитив #0, 1 ссылка,
992 → 960, полный анализ без G002, совместимость с экспортом, «Применить»/«Отмена»).

Сверка лога запущенного экземпляра: импорт фикстуры (ревизия 0), затем ещё пять
импортов других файлов (два отказа Unsupported, три открыты); событий предпросмотра,
правки, Undo/Redo, сохранения и вопроса о несохранённом нет; лог обрывается без
`native_shutdown`, сообщений о панике нет. `healed.glb` в `artifacts/manual-ui` и
других проверенных папках нет. Поэтому шаги 3–8 логом этого экземпляра не
подтверждены; возможно, снимки и проход сделаны в другом окне программы. Это
записано как заявление владельца, а не как сверенное доказательство.

Найденный дефект: во встроенных шрифтах egui нет «→» и «●» — в предпросмотре
стрелка и отметка «не сохранено» рисовались пустым квадратом. Исправлено (текст
«было N, станет M», отметка «*»), добавлен тест: все не-ASCII символы строковых
литералов UI должны быть в шрифтах.

## Ограничения и что не сделано

- Ручная приёмка UI (клики, горячие клавиши, нативные диалоги) не выполнялась —
  нужно разрешение владельца на ввод и захват экрана.
- Только G002 для одного примитива за действие; остальные виды ремонта не начаты.
- «Сохранить» поверх рабочего файла и смена рабочего пути не реализованы (решение 2).
- Dirty консервативен: Apply→Undo остаётся «не сохранено».
- DEVICE_LOST сохраняет только CPU-состояние.
- Текстуры перезаливаются при каждой публикации; переиспользование — оптимизация позже.
- Во время сохранения закрытие откладывается с сообщением в статусной строке.
