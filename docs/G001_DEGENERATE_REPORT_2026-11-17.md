# REPAIR-01: удаление вырожденных треугольников (G001) — отчёт 2026-11-17

Ветка `claude/g001-degenerate` от `main` (после PR #1). Основание —
[ADR-0032](DECISIONS/ADR-0032-degenerate-removal-plan.md); публикация, Undo/Redo,
проверка экспорта и Save Copy — без изменений из
[ADR-0031](DECISIONS/ADR-0031-atomic-edit-publication.md).

## Что сделано

- `ad_heal::plan_degenerate`: полное сканирование одного исходного примитива тем
  же точным предикатом нулевой площади, что и диагностика G001
  (`ad_analysis::zero_area`, теперь публичный). Удаляются треугольники с
  повторяющимся индексом и с тремя вершинами на одной прямой; допуска по площади
  нет (решение владельца 1). Полностью вырожденный примитив — явный отказ.
- Планы несут `RepairKind`; для G001 независимая проверка за один проход без
  дополнительной памяти доказывает: только удаление, порядок и обход выживших,
  точное совпадение удалённого набора с G001.
- Desktop: `EditKind::RemoveDegenerate`, кнопка «Предпросмотр ремонта…» в строках
  G001, окно предпросмотра с названием ремонта и пояснением; общий примитив
  затрагивает все ссылки (решение 2), предпросмотр показывает их число.
- Освободившиеся вершины остаются и видны как G003 — это REPAIR-02.

## Проверки

205 тестов (ad-heal 17, desktop 41); fmt --check, clippy all-targets
`-D warnings`, release-сборка, cargo-deny. RED→GREEN: тесты не компилировались
без API, затем прошли.

Нативные smoke с запрошенной sync-validation на `Geometry_Findings.glb`
(примитив #0: 5 треугольников, 2 ссылки, вырождены (0,1,3) — коллинеарный и
(0,0,1) — повторный индекс): предпросмотр 5 → 3, Apply/Undo/Redo, отказ GPU
upload сохраняет всё, Save Copy 1336 байт с повторным импортом, повторное
открытие — 3 треугольника, полный анализ, G001 нет; видимый вопрос при закрытии.
Регрессии G002, импорта, heal-smoke и пустого окна — PASS, 0 ошибок validation.
