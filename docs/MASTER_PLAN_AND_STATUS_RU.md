# Asset Doctor RT-PT 2.0 — полный план и состояние реализации

**Дата сверки:** 17 ноября 2026 года, Europe/Riga.

**Проверяемая версия приложения:** `dbd6091fb40c768117fbf550388172cfb30951fb`.

**Назначение документа:** единый план всего продукта, перечень уже работающих функций и оставшихся обязательств. Это снимок состояния указанного коммита; будущая реализация обновляет статусы здесь и в [матрице функций](FEATURE_PARITY_MATRIX.csv).

## Краткий ответ о прогрессе

Первоначальный план сохранён: **полноценный Windows Asset Doctor с диагностикой, безопасным ремонтом, ручным Rig, анимациями, Undo/Redo, сравнением и проверенным экспортом; затем RT, PT, Mixamo, autorig и retargeting**. Старую архитектуру не переносим. Функции создаются заново на Rust; Vulkan-рендерер отделён от данных и анализа.

Сейчас получился **работающий нативный просмотрщик статических GLB с материалами и ограниченной диагностикой геометрии**. Он ещё не является полноценной заменой старого Asset Doctor. Основная работа по редактированию, ремонту и сохранению модели впереди.

Внутри ядра уже появился **работающий index-command/history модуль**: подготовка удаления явно указанных треугольников, guarded apply, Undo/Redo, ветвление и бюджеты. Это CPU API; в desktop нет новых кнопок редактирования, Heal или экспорта. Контракт ADR-0026 принят. Добавлен внутренний static GLB exporter и Windows Save Copy backend по ADR-0028/0029: fresh reimport, сравнение и проверенная запись нового файла без замены существующего. Полный Heal/Save Copy в desktop остаётся следующим milestone по ADR-0027; [отчёт экспорта](STATIC_EXPORT_REPORT_2026-11-16.md) фиксирует границы.

Новый **CPU G002-планировщик** по ADR-0030 собирает все дубли выбранного исходного примитива, сохраняет первый представитель и независимо проверяет подготовленную команду. Он использует общую историю; textured plan → Apply → полный анализ → Undo/Redo → export → запись → native readback проверены на авторских fixtures. Это ещё не desktop Heal: source/material eligibility и атомарная публикация остаются следующей работой. [Отчёт](DUPLICATE_PLAN_REPORT_2026-11-17.md).

В исходном каталоге есть **66 функций/сценариев Legacy и 10 отдельных требований владельца**. Это начальная инвентаризация, а не доказательство исчерпывающего аудита. Все 76 строк сохранены в разделах 11–12. Дополнительные направления из ТЗ — окружение, надёжность, RT/PT, Mixamo и прочие — также включены в дорожную карту ниже, даже когда отдельной строки Legacy для них нет.

**Нельзя считать процент готовности по числу строк:** одна строка Rig/Export значительно крупнее переключателя панели. Статус «частично» означает только явно перечисленный работающий объём, а не почти завершённую функцию.

## 1. Основания и неизменные требования

Главный источник — предоставленный владельцем **Asset Doctor RT-PT 2.0 Get Starting.md**, в особенности §2.4, §5–8. SHA-256 прочитанного файла: `2EE532764B1B379B6320B1C674A7137D7C0A2550FEB11A93E939DC70F4C347DA`. Сам файл не изменялся. Дополнения из диалога: старую архитектуру не переносить; использовать предоставленный значок; разработку и самостоятельные проверки продолжать без обязательной ручной приёмки каждого этапа. Запрос на этот документ не является запросом на новые продуктовые функции.

Исходная инвентаризация Legacy привязана к source HEAD `17ca3549767aac78bf4ad51fa1c254c90dd15113` из [audit snapshot](../reference/audit-snapshot.json). Это source-наблюдения: работоспособность каждого старого нативного сценария независимо не подтверждена. Такой статус не переносится автоматически ни в PASS, ни в отказ от требования нового продукта.

Архитектурное предложение v0.1 имеет рекомендательный статус. Приняты независимое Rust-ядро, отдельный Vulkan-рендерер и разделение диагностики, ремонта, Rig и анимации. Конкретное число пакетов, универсальная шина событий и большой общий `ad-core` не являются обязательствами. Разбор предложений: [ARCHITECTURE_PROPOSAL_REVIEW](ARCHITECTURE_PROPOSAL_REVIEW.md).

Сохраняются следующие обязательства:

- Windows x64, Rust и прямой Vulkan; без React, Three.js, WebView и Tauri в новом продукте.
- Единственный исходный документ модели; GPU и UI не владеют авторской геометрией.
- Старые исходники, установленный Legacy, Arc-XRay и пользовательские модели остаются справочными источниками без изменений. Заимствуется назначение функций, а не код или структура старого приложения.
- Оригинал модели не перезаписывается при импорте, просмотре или диагностике. Ремонт должен иметь preview, контролируемое применение, проверку и откат.
- Команды проверяют ID и revision документа; для первого index-only CPU-подмножества это уже реализовано. Отменённая или устаревшая задача не может заменить актуальные данные; общие jobs и desktop edit publication ещё развиваются.
- Открытие файла, безопасный ремонт, Undo и экспорт являются разными этапами. Сохранение считается успешным после записи и проверки, а не после нажатия кнопки.
- Надёжный raster/PBR и базовый продукт предшествуют RT; RT предшествует PT; Mixamo/autorig/retargeting идут позднее. Ручной Rig нужен уже в базовом продукте.
- Наличие расширения GPU, компиляция или красивый скриншот сами по себе не означают готовность соответствующей функции.

## 4. Границы форматов, материалов и ресурсов

### 4.1. Поддержка данных

| Данные/режим | Сейчас | Дальнейшая работа |
|---|---|---|
| GLB 2 с одним embedded BIN, статические треугольники | Поддерживается в согласованном подмножестве | Расширять по compatibility matrix, сохраняя source fidelity |
| JSON `.gltf` | Не поддерживается | Отдельный контракт самодостаточного glTF и политика ресурсов |
| Внешние BIN/images/URLs | Отклоняются | Не открывать автоматически; новые способы доступа — отдельное решение |
| PNG/JPEG material maps | Поддерживаются с лимитами | Дополнительные форматы только с decoder/resource/лицензионными проверками |
| Source UV | F32 VEC2 или normalized U8/U16 VEC2; до восьми каналов; G009–G011 | Расширенная диагностика UV и позднее инструменты по отдельному контракту |
| Base color, vertex color, MR, normal, AO, emission | Поддерживаются перечисленные core-параметры и карты | Полная калибровка, дополнительные glTF material extensions |
| Tangents | Авторские данные сохраняются; при отсутствии применяется производная UV-основа | Fallback не заявлен как эквивалент MikkTSpace; нужна проверка швов/зеркал |
| Alpha | OPAQUE и MASK | BLEND, корректная сортировка и соответствие double-sided/culling |
| Skin, clips, morph targets | Явный отказ импорта | Данные/вычисление/рендер/экспорт отдельными этапами |
| Draco, Meshopt, KTX2/BasisU, quantization, texture transform | Не реализованы, соответствующие неподдерживаемые варианты отклоняются | Офлайн fixtures и сертификация каждого варианта × операция |
| Обязательные glTF extensions | Отклоняются | Список поддерживаемых расширений вводится явно |
| HDR/IBL, реальные тени, отражения окружения | Не реализованы | Отдельные raster-этапы до RT |
| RT/PT | Не реализованы | Этапы 9–10 |
| FBX/OBJ/USD и иные форматы | Не входят в текущий importer | Не обещаны как уже поддержанные; для поздних animation-workflows формат выбирается отдельно |

Сохранение оригинальных байтов — ещё не доказательство roundtrip изменённого файла. Принятый для просмотра ассет не считается автоматически пригодным для будущего ремонта или экспорта.

### 4.2. Текущие инженерные ограничения

Числа ниже прочитаны из `ImportLimits`, `ad-analysis::Limits`, UV и GPU-binding контрактов указанной версии. Это пределы допуска отдельных представлений, **не гарантия общего пика RAM/VRAM** и не окончательные лимиты релиза.

| Ограничение | Значение |
|---|---|
| Исходный файл | 192 МиБ |
| JSON chunk | 16 МиБ |
| Оценка decoded geometry/source UV | 512 МиБ |
| Оценка render snapshot | 512 МиБ |
| Узлы / развёрнутые draw-примитивы | 50 000 / 100 000 |
| Изображения sampled variants / сторона изображения | До 256 / до 8192 пикселей |
| Проспективное texture mip-хранилище | 256 МиБ по политике sampled-вариантов |
| Материальные наборы GPU | До 4096 уникальных tuple |
| Source UV на примитив | До 8 каналов; добавочная оценка 8 байт × вершины × каналы |
| Геометрия render snapshot/GPU | 96 байт на вершину + индексы по текущему контракту |
| Анализ | До 4 000 000 source-треугольников; 64 МиБ scratch на фазу; до 4096 findings; до 16 примеров на finding |
| CPU index history | По умолчанию 64 МиБ / 128 entries; фактическая capacity метаданных + max index capacities; отказ вместо eviction. Это пока не настройка UI |

32 ГБ RAM и 16 ГБ VRAM не складываются в единый бюджет. Объём heap из probe не равен свободной памяти. Stage buffers, старый опубликованный ресурс, декодирование, история и будущие acceleration structures требуют замеров/отдельного учёта.

## 5. Диагностика: 11 реализованных проверок

Сейчас `ad-analysis` использует **algorithm version 5**. Проверки выполняются над исходными примитивами документа, включая неактивные, по одному разу. Экземпляры сцены не умножают findings. Преобразования просмотра не меняют исходные индексы или результат анализа.

| Код | Реализованная проверка | Существенная граница |
|---|---|---|
| G001 | Треугольники с точно нулевой геометрической площадью | Robust-предикат, без эвристического порога «очень маленький» |
| G002 | Повторные треугольники с теми же индексами и направлением обхода | Циклическая перестановка учитывается; обратный winding не считается тем же ориентированным треугольником |
| G003 | Неиспользуемые исходные вершины | Проверка ссылок индексов, без автоматического удаления |
| G004 | Отсутствующие normals | Информационное замечание; fallback просмотра не исправляет исходник |
| G005 | Нулевые normals | Не является полной проверкой ориентации/согласованности нормалей |
| G006 | Граничные индексные рёбра | Информационно; открытая поверхность может быть намеренной |
| G007 | Рёбра с более чем двумя инцидентными гранями | Предупреждение; это часть топологии, а не полная manifold-сертификация |
| G008 | Несколько групп связности по общим индексам вершин | Информационно; это не число физических деталей. Общая вершина соединяет группы, совпавшие позиции не склеиваются |

Для рёбер и связности треугольники с повторяющимися индексами исключаются с явным счётчиком. Разные индексы с коллинеарными позициями могут участвовать в топологии. Между примитивами нет скрытого welding.

Отчёт содержит ID/revision/версию алгоритма, код/важность/count и типизированные примеры: вершины, треугольники, пары вершин рёбер, представители и размеры групп. При локальном ресурсном отказе сохраняются завершённые findings, а пропуски маркируются. Полная отмена задачи не публикует новый отчёт. Отсутствие findings не является health score или заключением о полной пригодности модели.

**UV-проверки также реализованы по контракту:** [ADR-0025](DECISIONS/ADR-0025-source-uv-diagnostics.md).

| Код | Назначение | Реализованный объём и граница |
|---|---|---|
| G009 | Отсутствует исходный UV0 | Информация, count 1 на source-примитив; канал материала не заменяет UV0 |
| G010 | Точно нулевая UV-площадь по каждому source-каналу | Warning, robust predicate; channel output атомарен; повторные индексы исключены, нет epsilon для tiny maps |
| G011 | UV-вершины вне замкнутого квадрата 0…1 | Информация по каждому каналу, включая unused vertices; повторение текстуры может быть намеренным |

Все каналы сохраняются и проверяются в указанном объёме. Без каналов G010/G011 получают статус «неприменимо», а не «проверено без замечаний». Coverage различает проверенные, неприменимые и пропущенные примитивы. Перекрытия/острова/плотность UV, orientation, materials, skeleton, weights, animations и профили пригодности пока не выполнены.

## 6. Архитектура: реализованные и будущие части

В workspace восемь пакетов, включая пока не подключённые к desktop модули команд, Heal-планирования и файловой записи. Наличие отдельного пустого crate не считается выполненной подсистемой. Рекомендательная схема не требует немедленно создавать все будущие пакеты. У renderer нет права стать владельцем авторских данных; анализ не зависит от Vulkan/UI.

## 7. Подробный оставшийся план и критерии готовности

Ниже — порядок зависимостей для дальнейшей работы. Это детализация исходного плана, а не замена его финальной цели. Конкретные алгоритмы, библиотеки и UX принимаются небольшими ADR перед соответствующей реализацией.

### P1. Завершить карту требований и аудит нужных операций

- Сопоставить все 197 лексически найденных UI sites с функциями/исключениями; это не 197 видимых кнопок.
- Классифицировать 110 кандидатов state и довести 60 исходных строк settings: defaults, min/max, reset, persistence, контексты.
- Закрывать ошибки/cancel/retry/unsaved/native-сценарии на уровне конкретного инструмента, не переписывая Legacy.
- Подготовить лицензированные fixtures и coverage «операция × extension × source fidelity» для Heal/Rig/Export.

**Готовность:** у каждой целевой операции есть источник требования, определённый результат, ограничения, ошибки и воспроизводимая проверка. Нативно не проверенный Legacy-сценарий так и отмечен; выполнение исходного кода не требуется ради галочки.

### P2. UV и дальнейшая read-only диагностика

- **Завершено:** G009–G011 поверх сохранённых source UV, N/A без каналов, атомарные многоканальные findings и сохранение предыдущих результатов при отказе; unit/native/full/partial UI проверки.
- Затем отдельными частями добавить целостность/ориентацию/дальнейшую топологию, материалы/текстуры, transforms/performance и профили.
- Дать фильтры, переход к дефекту/подсветку, rescan после изменения и экспорт диагностического отчёта.
- После появления skin/animation — их валидаторы, не подменять их отклонением импорта.

**Готовность:** известные дефекты дают ожидаемые коды/evidence; source и instance scope различимы; отмена/stale/лимиты проверены; пустой неполный отчёт не показывает успех.

### P3. Команды редактирования, общая история и пользовательская сессия

- **Выполнено в CPU index-only объёме:** ADR-0026, document/revision/origin guards, отдельный ad-commands, apply/Undo/Redo. Общее редактирование, transforms и camera/view-разделение остальных инструментов ещё развиваются.
- Зафиксировать стабильные ID, версии схем/контрактов, координатные базы/единицы и трансформации, ссылки materials/texture/skin/curves, сохранение extras/неизвестных extension-данных. Не менять авторские данные ради одного renderer backend.
- **Частично выполнено:** атомарный CPU index swap, отмена подготовки, Undo/Redo, ветвление и бюджеты. Gesture preview, reset original, eviction и атомарная desktop/GPU публикация впереди.
- Устаревший анализ/preview не применяется к новой revision; отказ по памяти не оставляет половину операции.
- Для долгих jobs определить document ID/revision, completed/cancelled/failed, структурированный error code, progress, метрики и trace ID. Текущий import worker не объявляется полной реализацией этого общего API.
- Ввести проекты/настройки и защиту от потери несохранённых правок; session history не считать автоматически частью GLB.

**Готовность:** операция → Undo → Redo восстанавливает точные данные; cancel ничего не меняет; source bytes остаются неизменными; worker старой версии не публикует изменения.

### P4. Безопасный экспорт — до объявления первого ремонта готовым

- **Выполнен внутренний subset ADR-0028/0029:** source primitive/accessor mapping, exact-copy либо append-only index writer, ограниченные core metadata, private origin/revision proof и Windows new-path запись с no-replace publication.
- **Проверено:** fresh reimport и точное сравнение hierarchy/transforms/indices/attributes/UV/materials/images; disk byte-readback, cancel, недоступный/занятый путь, corruption, concurrent publication, очистка по Windows-дескриптору и warning после опубликованного файла.
- **Осталось:** native Save dialog/cancel, dirty-state/unsaved-close и desktop workflow; никакого overwrite сейчас нет. Общий writer/opaque metadata/skin/animation/repair combinations требуют отдельных контрактов. Peak memory и directory power-loss durability не подтверждены.

**Готовность:** подтверждена запись корректного файла; исходник не перезаписан молча; неуспешная/отменённая запись не сбрасывает dirty protection. Путь Rig+Heal сертифицируется отдельно, а не следует автоматически из статического экспорта.

### P5. Heal и все семь исходных repair-операций

- Preview/dry-run, понятный diff/риск/ограничения; apply только к ожидаемой revision; verify после выполнения; отмена/rollback/история.
- Удаление degenerate triangles, unused vertices, exact duplicate triangles; пересчёт normals; exact vertex merge с корректным сохранением швов/атрибутов.
- После skin-data contracts: normalize weights и consolidate duplicate influences. Геометрическое совпадение не даёт права склеивать разные UV/normal/skin данные.
- Безопасная очередь перечитывает кандидатов после каждого шага, прекращается при регрессии/cancel/stale и не выполняет молча рискованные действия.
- Отчёт текущего подтверждённого ремонта отделён от сохранённой истории отчётов.

**Готовность каждой операции:** preview не меняет документ; apply устраняет целевой дефект без новых несогласованных потерь; Undo точен; результат проходит export/reimport. Ни одна из семи операций пока не завершена как desktop workflow. Для REPAIR-06 реализован CPU plan/postcheck и проверена цепочка с общей историей/экспортом; eligibility и native-публикация остаются обязательными.

### P6. Модели, лампы, полы, окружение и управление

- Translate/scale gizmo модели, numeric controls, локальные/мировые координаты, Undo и сохранение. Автовращение не добавлять.
- Лампа — редактируемый объект сцены; gizmo привязан к лампе, drag не двигает камеру и не вызывает скачок позиции.
- ПКМ-меню лампы: только реально поддержанные intensity/color/temperature/enable; согласовать правило temperature vs color, историю и persistence.
- Независимые окружение и лампы; HDR/IBL, shadows, темы/оттенки пола без дублей; сохранить выбранные параметры.
- Переназначение клавиатуры и кнопок мыши, включая боковые, конфликты/default/reset; input ownership UI/gizmo/camera.
- Дополнить render channels, shading, lighting presets, helpers, grid/axes/bounds/skeleton/origin и exploded view без изменения авторских transforms.

**Готовность:** видимые controls меняют именно обещанное состояние, сохраняются по контракту, Undo работает для edits, оригинал и управление камерой не повреждаются.

### P7. Skeleton/skin, ручной Rig и базовые анимации

- Расширить importer/document/snapshot/renderer для skins и clips; rest/bind/pose, inverse binds и skin weights имеют явную модель.
- Inspect/edit/pose; выбор суставов, translate/rotate/twist, числовые поля, local/world, поведение дочерних суставов.
- Создание/именование/длины/удаление joint/chain/skeleton, fitting-preview и отказ от stale/неуверенных предложений, reset и общая история.
- Timeline, поиск/выбор clip, autoplay по owner requirement; play/pause/stop/step/seek/loop/speed.
- Rename/retime clip, root-motion measurement/overlay и сохранение ключей. Скорость preview не подменяет экспортируемую длительность.
- Morph targets и дополнительные типы данных вводить по compatibility/parity matrix, с явным отказом неподдерживаемых операций.

**Готовность:** нет поломки rest pose/деформации; Undo возвращает bind/weights/clips; экспорт и повторный импорт совпадают структурно и в контрольных позах. Autorig/Mixamo не являются предварительным условием ручного Rig.

### P8. Автоматический single/Compare и многомодельная сессия

- 1 модель = single; 2+ = Compare, без отдельной обязательной кнопки режимов; общая панель настроек.
- Добавление/удаление/замена/выбор/solo, переходы 1→2→1, раскладки и real/manual scale matching.
- Независимые/синхронные камеры; позднее анимации и timeline. Целевой сценарий до восьми моделей унаследован как проверяемое требование, а не автоматический допуск восьми максимальных файлов.
- Изоляция document identity, edits/Undo/jobs/export; единая сессия не означает одну геометрию для всех ассетов.

**Готовность:** переходы не теряют данные, selection/историю/камеры; поздний job не заменяет другую модель; повторные add/remove не наращивают удерживаемую память. Старый ручной Compare и переход «открыть в Doctor» адаптируются к новой сессии, а не копируются буквально.

### P9. Настройки, recovery и качество Windows-поставки

- Настройки языка/тем/графики/ввода/ресурсной политики, сохранение/reset/миграции и ошибки storage.
- Продуктовые логи: ограничение объёма/retention, просмотр/save/clear, полезный контекст без секретов; crash/recovery и контролируемое завершение.
- Проверить альтернативы native UI, high DPI/несколько мониторов, клавиатуру/focus/accessibility, drag-and-drop и большие деревья.
- Измерить RAM/VRAM/временные копии/latency/cancel на static/textured/skinned/animated/Compare; ресурсы старых revisions освобождаются после GPU completion.
- Windows product ID/пути/install/uninstall/update, чистая машина, отсутствие конфликта с установленным Legacy, лицензия продукта и notices зависимостей.
- Отказы loader/features/allocations/device-lost: воспроизводимые безопасные стенды, fallback/восстановление по контракту.
- Security/format policy для недоверенных файлов: recursion/decompression/accessor/image limits, path traversal и shader inputs; зависимости — purpose/version/license/replacement, lockfile и vulnerability checks.
- Перед релизом — CHANGELOG, осмысленная версия/tag, перечень реально поддержанных функций и оставшихся ограничений. Product licensing отдельно от разрешённости библиотек.

**Готовность:** рабочая самостоятельная установка и нативный regression suite; продуктовые сценарии P0/REQ и экспорт закрыты. FPS/скорость и memory limits опираются на замеры.

### P10. Hardware RT

- Проверить и реально включить нужные features; extension names из старого probe не равны включённому RT.
- BLAS/TLAS build/update/rebuild для static и далее skin/animation; lifetime, барьеры, budgets и стоимость обновления.
- Первый ограниченный эффект, например shadows/reflections, затем hybrid raster+RT; UI качества и raster fallback.

**Готовность:** контролируемое сравнение RT on/off, frame time/VRAM, смена модели/анимация, unsupported-device поведение и validation. Не начинать, пока базовые raster/PBR/ресурсные contracts не стабилизированы.

### P11. Progressive PT

- Интегратор света/BRDF, прямое и непрямое освещение, multiple bounces, sampling, accumulation и при необходимости Russian roulette.
- Сброс накопления при изменении камеры, лампы, материала, модели/анимации; stale accumulation недопустим.
- SPP/max bounces, preview/final, выбранный denoiser, экспорт изображения и профили качества.

**Готовность:** визуальные эталоны, стабильное накопление/reset, проверенные кадры и лимиты памяти. PT не заменяет диагностику/Heal.

### P12. Mixamo, autorig, ручная коррекция и retargeting

- Перед поставкой animation assets проверить актуальные права Adobe/Mixamo и лицензии примеров. Этот документ не делает правового вывода и не предполагает права bundling.
- Если права на комплект не подтверждены — пользовательские лицензированные animation files, без встраивания чужой библиотеки.
- Autorig/skinning: определение суставов, binding/weights, повторный запуск, preview, ручная коррекция и Undo.
- Retargeting: mapping двух существующих skeletons, bases/scale/orientation, root motion, ограничения и контроль деформации.

**Готовность:** права установлены для выбранного способа поставки, результаты проверены на разных моделях, исправимы вручную и сохраняются через verified export. Эти направления не объединяются в одну необъяснимую кнопку.

### 8.2. Обязательная готовность каждой следующей функции

1. Требование и точный объём: связь с ID/REQ, контракт и ограничения.
2. Проверка, обнаруживающая отсутствие поведения, затем рабочая реализация; meaningful regression.
3. Ошибка/cancel/retry/stale и ресурсный отказ; для edits — Undo/Redo и source preservation.
4. Для видимого инструмента — реальное native/UI/GPU выполнение; для exporter — fresh reimport и disk-write/cancel/failure.
5. fmt/clippy/tests/locked Windows build и dependency policy по релевантному изменению.
6. Source review и обновление этого плана, матрицы, tasks/pulse и соответствующего отчёта.

Документ/ADR со статусом accepted является контрактом, а не автоматически выполненной функцией. Probe, unit, native, visual и ручная приёмка владельца — разные виды доказательств.

## 9. Незакрытые вопросы и отклонения от плана

- **Общий аудит не завершён.** Исходное требование полного аудита всех UI/settings до продуктовых модулей ещё не закрыто. Фактически продукт разрабатывался через отдельные исследованные и согласованные subsets; это не равнозначно закрытию общего gate. Перед Heal/Rig/Export особенно важно закрыть их fidelity/operation-неизвестности.
- **Документация отстала в отдельных местах.** До этой сверки матрица отмечала ряд работающих controls/логов/лимитов как NOT_STARTED; некоторые checkpoints содержали старые числа тестов и запрет push, действовавший на момент их написания. Матрица и текущие указатели синхронизированы; исторические отчёты остаются снимками своих версий.
- **Функциональный паритет не достигнут.** Нельзя назвать новый просмотрщик законченным Asset Doctor до Heal/Rig/Animation/Undo/Compare/Export/settings/recovery.
- **Объём импорта ограничен сознательно.** Статическая GLB-поддержка не означает glTF, compressed/skin/animation или export fidelity. Недопустимые данные отклоняются явно, но отсутствие поддержанного формата всё равно остаётся незавершённым требованием.
- **Рендер предварительный.** Нет HDR/IBL/shadows, BLEND и полного culling parity; нет точной Mikk/BRDF-пиксельной калибровки. Наличие direct PBR не закрывает этап raster-quality.
- **Нет пользовательского интерфейса редактирования.** CPU index-command/history уже работает, но общего редактора, desktop/GPU-транзакции, native Undo shortcuts и Heal workflow ещё нет. Snapshot сам по себе не является Undo.
- **Продуктовая поставка ещё не создана.** Папка с EXE не заменяет независимый установщик, product ID, storage schema, recovery и clean-machine acceptance.
- **Нет достоверной даты готовности или процента.** Сроки следующих крупных подсистем требуют измерения после contracts; искусственный процент по строкам ввёл бы в заблуждение.

## 13. Ближайшая последовательность и поддержание документа

Следующая рекомендуемая последовательность без изменения общей цели:

1. **Завершено:** G009–G011 и source/coverage/UI/native проверки по ADR-0025; следующая работа начинается с пункта 2.
2. **Внутренние prerequisites выполнены:** CPU index-command/history ADR-0026, static export/storage ADR-0028/0029 и полный G002 plan/postcheck ADR-0030. Следом закрыть оставшуюся часть ADR-0027: source/material eligibility, native preview и атомарную desktop/history/analysis/snapshot/GPU publication. **17.11.2026:** протокол публикации и решения владельца приняты в [ADR-0031](DECISIONS/ADR-0031-atomic-edit-publication.md) (только документ, код не менялся); реализация по этапам B1–B4 → C → D из ТЗ-G002; B1 (снимок и анализ кандидата без мутации) выполнен. Не расширять бесконечно только просмотрщик, оставляя основные инструменты без движения.
3. Довести минимальный сквозной сценарий: известный дефект → preview → apply → verification → Undo/Redo → Save Copy → fresh reimport. Только после него считать первый Heal перенесённым.
4. Последовательно расширять diagnostics/Heal и поддержанные форматы; затем skin/manual Rig/animation, auto-Compare и полный UX согласно зависимостям P1–P9.
5. Закрыть release-quality raster и проверяемые P0/REQ, затем RT → PT → Mixamo/autorig/retargeting.

Это порядок разработки, не утверждение, что все contracts уже приняты. Требование пользователя «делай без моей приёмки» снимает обязательное ожидание ручного PASS каждого этапа, но не отменяет проверки и честную фиксацию границ.

Правило обновления: после каждого функционального этапа менять соответствующие строки §11–12 и `FEATURE_PARITY_MATRIX.csv`, критерии этапа, `tasks/todo.md` и `Project-pulse.md`. Отчёты по старым версиям сохранять как историю. При новой сверке фиксировать новый code SHA и не переносить PASS со старой сборки автоматически.

`tools/audit_legacy.py` создаёт исходную инвентаризацию и при повторном запуске может заново выставить начальные статусы. Его вывод нельзя без проверки подменять текущей матрицей прогресса. Сам генератор в этой документационной задаче не менялся и не запускался.
